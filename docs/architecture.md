# 架构设计

本文档说明 `obsfast` 的整体结构、模块职责、并发模型与关键设计取舍。面向需要在本实践基础上做二次开发或排障的读者。

## 1. 定位与能力边界

`obsfast` 是一个命令行工具，用于**大规模对象存储桶的并发盘点与双桶差异比对**。它解决的问题是：当桶内对象数量达到千万甚至十亿级时，单线程顺序列举会耗费数小时乃至数天，且无法横向扩展。

核心能力：

| 能力 | 子命令 | 说明 |
|-|-|-|
| 单桶并发盘点 | `list` | 按前缀区间并行列举，导出前缀分布与对象元数据 |
| 双桶差异比对 | `diff` | 两侧并发列举并逐键比对，导出差异项 |
| 键空间切分 | `split` | 由前缀分布文件生成提示，把大盘点任务切成可并行的区间 |
| 桶清单解析 | `inventory` | 解析服务端生成的清单报告，直接产出前缀分布 |
| 清单规则管理 | `inventory-config` | 配置 / 查看 / 删除桶上的清单规则 |

边界：本工具**只读不写业务数据**。除 `inventory-config` 会修改桶上的清单规则配置外，其余子命令对桶只发起列举与读取请求。

## 2. 目录结构

```
src/obsfast/
├── __main__.py        命令行入口（python -m obsfast）
├── cli.py             参数解析、子命令编排、结果汇总与退出码
├── config.py          区域 / 端点 / 凭据 / 运行参数
├── model.py           对象元数据模型、匹配语义、错误分类
├── obs_client.py      对象存储 REST 访问层：头签名、列举、读写对象
├── listing.py         并发盘点调度：区间领取、分页、批次投递
├── data_map.py        前缀映射、键空间提示、切分算法
├── filter_expr.py     过滤表达式（受控 DSL）
├── inventory.py       桶清单：规则配置、manifest 解析、清单转前缀分布
├── parquet_writer.py  Parquet 导出
└── monitor.py         心跳与统计输出
```

## 3. 模块职责

### 3.1 访问层 `obs_client.py`

本实践**不使用任何第三方 SDK**，直接用标准库实现对象存储的 REST 访问，原因有二：桶清单的接口（`PutBucketInventory` / `GetBucketInventory` / `ListBucketInventory` / `DeleteBucketInventory`）在常见 SDK 中没有封装；零第三方依赖也让工具在受限环境中更易分发。

关键实现点：

* **头签名**：`StringToSign` 由 `HTTP方法`、`Content-MD5`、`Content-Type`、`Date`、规范化头、规范化资源六部分拼成，用密钥做 HMAC-SHA1 后 Base64 编码，最终形如 `Authorization: OBS {访问键}:{签名}`。
* **寻址方式**：默认**虚拟主机风格**（`{桶名}.obs.{区域}.myhuaweicloud.com`）。使用自定义端点时自动切换为路径风格，也可由 `--path-style` 强制。服务端对区域域名强制要求虚拟主机风格，路径风格会返回 `403 VirtualHostDomainRequired`。
* **时间字段**：服务端在同一响应族里混用 ISO 8601（`2026-10-15T03:46:45.555Z`）与 RFC 1123（`Mon, 28 Sep 1970 06:00:00 GMT`）两种表示，访问层统一归一为 Unix 秒。
* **XML 解析**：按**本地名**查找节点，不依赖服务端返回的命名空间取值，避免命名空间变更导致解析整体失效。

### 3.2 调度层 `listing.py`

采用「固定线程池 + 区间领取」模型：

1. 主线程把键空间切成若干区间，放入提示队列；
2. 工作线程循环调用 `hints.next()` 领取区间，领完即退出；
3. 单个区间内由 `flat_list` 顺序分页，每页结果作为一个批次投递给汇总侧；
4. 区间扫描到末尾时，用**字典序上界**（`until`）截断请求，避免越界读到相邻区间的数据。

并发度由 `--concurrency` 控制（同时进行的区间任务数，默认 100），线程池大小由 `--threads` 控制（默认 10）。

### 3.3 键空间与切分 `data_map.py`

前缀分布文件（`.ks`）记录每个「目录前缀」下的对象数量。`split` 子命令按数量做贪心累积：

```
avg_target = 对象总数 / 目标段数
累计计数超过 avg_target 时，在最后一个前缀处设一个切分点
```

产出 N 个切分点后，提示文件被读回时展开为 **N+1 个区间**：`["", k1)`、`[k1, k2)`、……、`[kn, 末尾)`。

> 提示文件的格式是**每行一个前缀**。解析时若遇到含逗号的行，会回退到 CSV 解析取首个字段，以兼容直接传入前缀分布文件的用法。

### 3.4 过滤表达式 `filter_expr.py`

过滤条件不使用 `eval`，而是**受控的递归下降解析器**，编译期即完成白名单校验：

* 可用变量仅 `SOURCE`、`TARGET`（`diff` 模式下两者皆可用，`list` 模式仅 `SOURCE`）；
* 可用属性仅 `size`、`last_modified`；
* 支持比较、逻辑与算术运算符；
* 引用未授权变量或属性（如 `SOURCE.etag`、`OTHER.size`）会在启动时报错，而不是运行期静默出错。

### 3.5 清单通路 `inventory.py`

桶清单由服务端按日 / 周周期生成，产物落在：

```
{目标前缀}/{源桶名}/{清单名称}/{yyyy-MM-ddTHH-mmZ}/manifest.json
```

`manifest.json` 描述数据文件清单（`fileSchema` 给出列定义），同级的 `files/` 目录存放数据文件。两处刻意偏离「按固定格式假设」的常规写法：

1. **键所在列按 `fileSchema` 动态定位**，而不是写死第 2 列——可选字段会影响列序；
2. **数据文件是否压缩按内容识别**（gzip 魔数 `1f 8b`），而不是按扩展名——不同版本导出的后缀并不统一。

## 4. 一致性判定口径

`diff` 对同名键先比大小、再比内容标识（ETag）。**这里有一个必须显式处理的服务端行为差异**：

当桶使用 KMS 默认加密时，列举结果中的 ETag **不等于**对象内容的 MD5，且同一内容重复上传会得到不同取值。此时若仍按 ETag 判定，会把全部对象误判为「两侧不一致」。

处理策略：

* 开跑前自动探测两侧桶的加密方式；
* 任一侧启用 KMS 加密时，自动降级为「仅按大小判定」，并打印告警与结论口径说明；
* 用户可用 `--no-etag-compare` 显式指定该口径。

> 因此，在 KMS 加密场景下，「两侧一致」的准确含义是**大小一致**，不包含内容是否相同的结论。

## 5. 输出物

### 5.1 前缀分布文件（`.ks`）

每行 `"前缀","对象数"`，第二列即该前缀下的对象计数：

```
"/","1"
"alpha","1"
"data/2024","2"
```

### 5.2 对象元数据（`.parquet`）

| 字段 | 类型 | 说明 |
|-|-|-|
| `Key` | string | 对象键 |
| `Size` | uint64 | 字节数 |
| `LastModified` | uint64 | Unix 秒 |
| `ETag` | string | 内容标识；KMS 加密场景下不等于内容 MD5 |
| `DiffFlag` | uint8 | 差异结论，见下表 |

`DiffFlag` 取值：

| 值 | 含义 | 默认导出 |
|-|-|-|
| 0 | 两侧一致 | 否（加 `--include-equal` 时导出） |
| 1 | 仅源桶存在 | 是 |
| 2 | 仅目标桶存在 | 是 |
| 3 | 两侧都有但元数据不一致 | 是 |

单桶 `list` 时所有记录标记为 `1`。Parquet 写出使用 `version="1.0"`、`compression="GZIP"`、`compression_level=6`。

## 6. 错误处理与续跑

错误按编号分类，并区分「可续跑」与「终止」：

| 编号 | 含义 | 续跑 |
|-|-|-|
| 16 | 桶不存在 | 否 |
| 17 | 访问被拒绝（凭据或权限问题） | 否 |
| 18 | 永久重定向（区域不匹配） | 否 |
| 1 | 下一页请求超时 | 是 |
| 2 | 客户端通用错误 | 是 |
| 3 | 连接超时 | 是 |

可续跑错误会让当前区间**从断点继续**而不是整体失败；不可续跑错误会请求全局退出并给出非零退出码。请求级状态码由 `HttpStatusTracker` 汇总，运行结束时打印分页次数与各类错误计数。

## 7. 约束与限制

| 约束 | 说明 |
|-|-|
| 列举单页上限 | 1000，由服务端固定，访问层不尝试突破 |
| 清单规则数量 | 每桶最多 10 条 |
| 清单生成频率 | 仅 `Daily` / `Weekly` |
| 清单文件格式 | 仅 `CSV` |
| 清单目标桶 | **不能是 KMS 加密桶**，服务端会返回 `400 InvalidArgument` |
| 端点风格 | 区域域名强制虚拟主机风格；路径风格仅适用于自定义端点 |

最后一条已固化到基础设施代码中：清单目标桶不启用 KMS 默认加密，详见 `infra/main.tf`。
